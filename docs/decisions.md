# Решения и соглашения

Журнал решений, принятых при обсуждении ТЗ и разработке. Новые записи — сверху.

## Шрифт Suisse, две кривые, дизайн-система Maytoni (v0.4, 12.11.2026)

### Решения заказчика
- Шкала каталога (внешняя дуга и кольца) — **подтверждена**.
- Шрифт графиков — **Suisse Intl**.
- Несимметричные светильники: **две кривые (C0–C180 и C90–C270), обе залиты**; C90–C270 — пунктиром,
  который не сливается с точечной сеткой: штрих 1,2 / 0,6 мм против точек сетки 0,15 / 0,45 мм.
  Обе кривые чёрные; все заливки лежат под контурами.
- Перекрытие кривых (образец TR106-2-12W / 18W, MATLAB): каждая кривая залита CMYK 0/0/20/0, область,
  где они перекрываются, — отдельной фигурой CMYK 0/0/36/0 (без прозрачности, печатается одинаково).
  Фигура строится по направлениям: радиус — меньший из двух (при трёх и более кривых — второй по величине),
  в точках пересечения кривых добавляются вершины. Цвет перекрытия задаётся в стиле.
  В образце обе линии сплошные; по решению заказчика C90–C270 у нас пунктиром.
- Оформление приложения — по дизайн-системе Maytoni («Расчёт освещения», Track Configurator).

### Шрифт Suisse Intl
- Шрифт коммерческий, в публичный репозиторий его положить нельзя (так же устроен «Расчёт освещения»:
  он ссылается на установленный «Suisse Intl»). Подключение:
  - «Взять Suisse Intl с компьютера» — Local Font Access API (Chrome, Edge), браузер спрашивает разрешение;
    берутся начертания Regular (≈400) и Medium (≈500, для полужирного);
  - «Загрузить файлы OTF/TTF» — одно или несколько начертаний одного семейства.
  Подключённый шрифт хранится в браузере (localStorage) и используется на экране и в экспорте.
  Пока он не подключён — встроенный Roboto и подсказка на панели графика.
- PDF: OTF с контурами CFF (Suisse поставляется так) fontkit встраивает с ошибками — просмотрщик считает
  шрифт повреждённым. Поэтому с CFF-шрифтом текст в PDF идёт кривыми; TrueType встраивается подмножеством.
  Начертание встраивается, только если им что-то написано. Редактируемый текст с Suisse — в SVG
  (у получателя должен быть установлен Suisse Intl).

### Интерфейс
- Токены и компоненты дизайн-системы Maytoni: фон #F0F0F0, карточки 12 px, акцент #7C54FE,
  кнопки-«таблетки», вкладки в шапке, светлая / тёмная тема (переключатель в шапке), шрифт Suisse Intl
  с запасными Helvetica Neue / Arial. Логотип — из «Расчёта освещения».

## Оформление каталога MAYTONI и EPS (v0.3, 12.11.2026)

### Приёмка этапа 3 (заказчик, 12.11.2026)
- Графики сверены с Viso / LDT Editor — совпадают. Сторона полярной КСС **подтверждена**: C0 справа.
- SVG и PDF в Illustrator открываются правильно. EPS с текстом-шрифтом (Type 42) Illustrator
  не понимает: подставляет системный шрифт по кодам символов, текст превращается в квадраты.

### EPS — текст всегда кривыми
- Встраивание Type 42 убрано. Образец каталога (MATLAB) сделан так же. Редактируемый текст — в SVG и PDF.

### Оформление «каталог MAYTONI» (по образцу «LIC eps stage2», 110 файлов)
- Полярная КСС-«иконка»: 39,1 × 22,3 мм (110,83 × 63,13 пт), R = 15,3 мм, кегль 6 пт, линии 0,3 пт,
  сетка пунктиром 0,43 / 1,29 пт, всё K100, заливка под кривой CMYK 0/0/20/0 (RGB 255/255/204).
- Заголовок «Iₘₐₓ = 442 cd/klm»: Iₘₐₓ — целое без разделителя разрядов, «max» — индекс 0,71 кегля.
- Нижняя полусфера, лучи через 30°, подписи 0°…90° снаружи, кольца без подписей.
- Шкала (сверена со всеми 90 образцами, у которых есть файл в библиотеке):
  максимум — Iₘₐₓ вверх до кратного 0,5·10ⁿ, при первой цифре 1 — ещё до кратного 0,2·10ⁿ
  (берётся меньшее): 1033 → 1200, 1421 → 1500, 2065 → 2500, 442 → 450, 38980 → 40000.
  Кольца — шаг 1, 2 или 5·10ⁿ, наибольший, при котором на максимум приходится ≥ 2,4 шага.
- Все образцы осесимметричные (одна кривая). Несимметричные — см. v0.4 (две залитые кривые).
- Шрифт образца — Helvetica; фирменный — Suisse Intl (v0.4).
- Оформление каталога и стиль «MAYTONI каталог» — по умолчанию для новых пользователей; стандартное
  оформление и нейтральный стиль остаются на выбор. В стиль добавлены заливка под кривой и пунктир сетки.

## Просмотр и графики (v0.2, 12.11.2026)

### Устройство
- График строится как «сцена» (src/charts/scene.ts): примитивы в миллиметрах, ось Y вниз, цвет — пара
  RGB + CMYK. Один построитель на график, три рендера: SVG (и экран, и экспорт), PDF, EPS.
  Поэтому экспорт совпадает с тем, что видно на экране.
- Группы сцены (grid, curves, labels, title, legend) в SVG становятся слоями: Illustrator берёт имя из id,
  Inkscape — из inkscape:label.

### Полярная КСС
- γ = 0° (надир) внизу, 180° вверху. Плоскость C — справа, C + 180° — слева; сторона переключается.
  **Подтверждено** заказчиком по Viso / LDT Editor.
- Плоскости по умолчанию: осевая симметрия — одна кривая «C0–C180»; иначе C0–C180 и C90–C270.
  Можно добавить до 6 пар (C30–C210 и т. п.). Тип B показывается после пересчёта в C (5° / 2,5°).
- Диапазон «авто»: нижняя полусфера, если выше 90° сила света не превышает 0,5 % от максимума,
  иначе вся сфера. Можно задать явно 0…90° или 0…180°.
- Шкала — «красивая» (шаг 1, 2, 2,5 или 5 × 10ⁿ, до 5 колец) или с заданным максимумом;
  при заданном максимуме кривая выше него идёт по внешнему кольцу.
- Подписи колец: в полной сфере — вдоль оси 180° под линией кольца, в нижней полусфере — под осью 90°.

### Линейная КСС
- По оси X γ от −90° до 90° (или −180…180°): плоскость C — в плюс, C + 180° — в минус.

### Единицы
- кд/клм считаются от потока: относительная фотометрия — поток ламп; абсолютная с заявленным
  потоком (LDT) — этот поток; абсолютная без потока (IES lumens = −1) — расчётный поток.
  Так значения совпадают с числами в самом LDT.
- Строка над графиком: расчётный поток Φ и Iмакс в выбранных единицах.

### Шрифты и экспорт
- Шрифт графиков по умолчанию — Roboto (Apache 2.0, есть кириллица и немецкие буквы), лежит в
  public/fonts. Можно подключить свой TTF/OTF (фирменный); он хранится в браузере.
- SVG — только RGB; текст — элементы `<text>` с именем шрифта. Если шрифта нет у получателя,
  редактор подставит похожий; для точного вида — PDF или EPS.
- PDF — pdf-lib: шрифт встраивается подмножеством (CID TrueType + ToUnicode, текст выделяется и
  редактируется), цвета DeviceRGB или DeviceCMYK.
- EPS — PostScript Level 2, EPSF-3.0, 7-битный. ~~Шрифт Type 42~~ — с v0.3 текст всегда кривыми (см. выше).
- Опция «текст кривыми» для PDF — когда у типографии нет шрифта.
- Имя файла при выгрузке одного графика: «<имя исходного файла>_polar.svg» / «_linear»,
  для CMYK — «_cmyk». В Chrome / Edge открывается системный диалог, имя можно поправить.
  Пакетная выгрузка (этап 5) — по папкам polar/, linear/, как решено в ТЗ.

### Стиль
- До получения образца заказчика (v0.2) — нейтральный стиль (src/charts/style.ts). Фирменный стиль
  задаётся в окне «Стиль графиков»: кегли, цвета RGB + CMYK, толщины, штрихи, шаг сетки;
  сохраняется в браузере и выгружается / загружается файлом JSON (для пакетной выгрузки).

### Прочее
- На вкладке «Паспорт» — «Сохранить как IES / LDT» (писатели ядра v0.1), чтобы проверять файлы
  в DIALux / Relux до этапа 5.
- Таблица сил света показывает сетку файла как есть (тип B — в H × V); симметрию можно развернуть.
- Сайт публикуется на GitHub Pages workflow-ом `pages.yml` (Settings → Pages → Source: GitHub Actions).
- Библиотека pdf-lib загружается только при первом экспорте PDF / EPS.

## Ядро форматов (v0.1, 12.11.2026)

### Модель
- Силы света внутри хранятся в абсолютных канделах. Тип фотометрии (абсолютная / относительная),
  потоки ламп и специфичные поля форматов сохраняются, чтобы файл записывался обратно в исходном виде.
- Хранятся только плоскости, которые есть в файле, плюс тип симметрии. Значение в любом направлении
  получается свёрткой по симметрии и билинейной интерполяцией (`intensityC`).
- Система координат типа C — как в EULUMDAT: γ = 0° надир, C0 — вдоль длины, C90 — поперёк.

### LDT
- Силы света (кд/клм) относятся к **первому** комплекту ламп; остальные комплекты — альтернативные лампы.
  Так устроены файлы GU10 в библиотеке (6 комплектов).
- Абсолютная фотометрия: число ламп −1, поток = поток светильника (как пишет DIALux).
- Коэффициент пересчёта (строка 24) применяется к силам света при чтении; при записи пишется 1.000,
  а коэффициент уже учтён в силах света (LORL пересчитывается). **Подтверждено** в DIALux:
  DL094-GU10-W @ 45.ldt — 498 лм (600 лм лампы × 0,83). В библиотеке этим коэффициентом задают
  КПД светильника для файлов GU10, где поток указан для лампы; парные IES этих светильников
  содержат поток лампы, а не светильника.
- Isym 3: хранятся плоскости C270…C0…C90 (индексы спецификации mc1 = 3Mc/4 + 1). В модели они
  отражаются в C90…C270 (I(C) = I(180° − C)). **Проверить** на файле из DIALux: в библиотеке нет ни одного
  файла с Isym 3.
- Isym ≠ 0, но записаны все Mc плоскостей → файл читается как несимметричный (так у O015SL-L3W3K.ldt).
- Isym 0 и Mc = 1 → осевая симметрия.
- При записи C-плоскости должны быть равномерными и делить 360° нацело; иначе пересчитываются на
  ближайший подходящий шаг (с замечанием). Осевая симметрия пишется как Mc = 1, Dc = 0 (как в библиотеке).
- DFF и LORL при записи пересчитываются по данным. Коэффициенты использования (строка 27) переносятся
  из исходного LDT, для IES пока пишутся нули — расчёт будет на этапе 6.
- Недопустимый Ityp (например 49) при записи заменяется: 1 для осевой симметрии, иначе 3.

### IES
- Запись — LM-63-2002, размеры в метрах, множитель 1 (исходный множитель уже применён).
- Нестандартные ключевые слова ([_SEARCH_CRI], [_SEARCH_COLORTEMP] и др.) сохраняются.
  Цветовая температура и CRI лампы берутся из них и пишутся в них же.
- Повторяющееся известное ключевое слово: берётся первое значение, при записи дубликаты убираются.
- Артикул — [LUMCAT], название — [LUMINAIRE] (LDT: строки 10 и 9).

### Тип B
- Читается и пишется в IES как есть. Для LDT и расчётов пересчитывается в тип C (по умолчанию шаг C 5°, γ 2,5°).
- Соглашение пересчёта: ось прибора → надир, полярная ось B → C90–C270, +V к C0, +H к C90.
  **Подтверждено** сверкой с DIALux на O443WL-L12GF3K.IES: направление вниз, поток 973 лм.
  Повернуть результат можно будет операцией поворота.
- Свет за пределами измеренной области B теряется — выдаётся предупреждение, если на границе > 1 % от максимума.

### Имена файлов
- По умолчанию выходной файл называется как исходный (в библиотеке имя = артикул с вариантом «@ 3000K»).
- Генерация вариантов: «<артикул> @ <суффикс>».

## ТЗ (12.11.2026)
- Хостинг — GitHub Pages, репозиторий публичный; код передаётся файлом `photometry-editor.bundle`.
- Языки интерфейса: ru, en, de; язык подписей на графиках выбирается отдельно.
- Векторный экспорт: SVG (RGB), PDF и EPS (RGB и CMYK); цвета стиля задаются парой RGB + CMYK.
- Повороты вокруг X, Y, Z — отдельными шагами в порядке, заданном пользователем.
- Сложение тел учитывает смещение (по умолчанию 0); в итоговом IES/LDT — сумма в дальней зоне.
- Инструмент внутренний: без аккаунтов и монетизации.
