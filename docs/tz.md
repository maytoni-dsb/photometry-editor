## Цель продукта

Браузерный инструмент для просмотра, редактирования, конвертации и пакетной обработки фотометрических
файлов IES и LDT, рассчитанный на светотехника. Пользователи — заказчик и его коллеги.

Отличия от бесплатных Viso Photometric Editor и PhotoView, ради которых продукт делается:

- пакетная обработка файлов по заданной цепочке операций;
- пакетная выгрузка графиков в векторном виде;
- операции над фотометрическими телами: нормировка, отражение, поворот, сложение;
- файлы не покидают компьютер пользователя: вся обработка идёт в браузере.

## Архитектура и технологии

Приложение работает целиком в браузере, без сервера; сервер добавляется только если понадобятся аккаунты
или облачное хранение.

- **Единая внутренняя модель фотометрии.** Сетка C-γ, силы света в абсолютных канделах, метаданные,
  исходный тип фотометрии (абсолютная / относительная) и поток ламп. Любой формат читается в эту модель
  и пишется из неё, все операции работают только с ней. При записи файл возвращается в исходный вид:
  LDT — в кд/клм, IES с относительной фотометрией — с потоком ламп и множителем. Нормировка к 1000 лм —
  отдельная операция.
- **Ядро отдельно от интерфейса.** Парсеры, операции и расчёты — отдельный модуль без UI, полностью
  покрытый автотестами на эталонных файлах.
- **Собственный SVG-рендер графиков.** Один и тот же код рисует график на экране и выгружает его
  в SVG/PDF/EPS, поэтому векторный экспорт получается без потерь. Цвета стиля задаются парой RGB + CMYK,
  и при выгрузке выбирается режим: RGB для экрана или CMYK для печати (CMYK — в PDF и EPS; SVG его
  не поддерживает).
- **Пакетная обработка в фоновом потоке (Web Worker)**, чтобы интерфейс не зависал на сотнях файлов;
  результат выгружается ZIP-архивом.
- **Стек:** TypeScript, React, Vite; 3D — three.js; ZIP — JSZip; локализация — i18next, все тексты
  в файлах переводов (ru, en, de) с первого дня; PDF — генерация на клиенте.
- **Инфраструктура:** репозиторий на GitHub, автотесты при каждом изменении, хостинг на GitHub Pages;
  сборка и публикация автоматически через GitHub Actions при каждом изменении в основной ветке.

## Форматы файлов

В первой версии — IES и LDT на чтение и запись, графики в SVG и PDF; остальное по мере необходимости.

| Формат | Чтение | Запись | Приоритет |
|---|---|---|---|
| IES LM-63-1995 / 2002 | да | да | P1 |
| IES LM-63-2019 | да | да | P1 чтение, P2 запись |
| EULUMDAT (.ldt), все Isym 0–4 | да | да | P1 |
| TM-33-18 (XML) | да | да | P3 |
| Фотометрия типа B (встречается в лабораторных IES) | да | да | P1 чтение и пересчёт в C, P2 запись |
| График SVG (RGB, для экрана и веба) | — | да | P1 |
| График PDF (векторный), RGB и CMYK | — | да | P1 |
| График EPS, RGB и CMYK | — | да | P1 |
| График PNG | — | да | P2 |
| График EMF / DXF | — | да | пока не планируется |
| Сводная таблица параметров CSV / XLSX | — | да | P1 |

Парсер терпим к нарушениям стандарта (лишние переносы строк, нестандартные ключевые слова, TILT),
при записи соблюдается стандарт строго. Ошибки и исправления в файле показываются пользователю списком.

## Функции и приоритеты

P1 — первая рабочая версия, P2 — следующая, P3 — потом. Пункты, которых нет в бесплатных Viso и PhotoView,
стоят в P1.

| Группа | Функция | Что входит | Приоритет |
|---|---|---|---|
| Операции над телом | Нормировка | К заданному потоку (лм), к 1000 лм (кд/клм), к заданной максимальной силе света, умножение на коэффициент | P1 |
| Операции над телом | Отражение | Относительно плоскостей C0–C180 и C90–C270; верх/низ (γ → 180° − γ) | P1 |
| Операции над телом | Поворот | Вокруг вертикальной оси (Z) на любой угол: сдвиг C-плоскостей с интерполяцией на исходную сетку | P1 |
| Операции над телом | Поворот вокруг X и Y | Произвольная ориентация тела, в том числе для исправления «некорректных» файлов из лаборатории. Для каждого узла новой сетки C-γ направление поворачивается обратно, сила света берётся 2D-интерполяцией по исходной сетке; симметрия заранее разворачивается до полной (Isym 0). Каждый поворот — отдельный шаг; шаги применяются в порядке, заданном пользователем, с предпросмотром. Знак угла — по правилу правой руки: +X наклоняет надир к C90, +Y — к C180, +Z переводит C0 в C + угол (подтвердить на приёмке). В P2 — автовыравнивание по оси максимума или центру тяжести КСС | P1 |
| Операции над телом | Сложение | Сумма нескольких тел, у каждого свой вес, поворот и смещение (x, y, z; по умолчанию 0). В итоговом IES/LDT силы света суммируются в дальней зоне, светящие размеры расширяются до охватывающих все компоненты. Смещения сохраняются в файле сборки и учитываются в расчётах освещённости на конечном расстоянии; при расстоянии меньше 5 размеров сборки — предупреждение | P1 |
| Операции над телом | Симметризация, смена сетки | Усреднение по типу симметрии, интерполяция на заданный шаг C и γ. Сглаживание (v0.9): гауссово ядро на сфере 0…30°, с сохранением потока | P1 |
| Пакетная обработка | Рецепт операций | Цепочка операций применяется к набору файлов; рецепт сохраняется и используется повторно | P1 |
| Пакетная обработка | Конвертация | IES ↔ LDT для набора файлов, имя выходного файла запрашивается при сохранении, по умолчанию — артикул, выгрузка ZIP | P1 |
| Пакетная обработка | Генерация вариантов | Из одного файла — набор файлов «@ 4000K» и т. п. с другим потоком, ЦТ, CRI, мощностью и лампой; см. раздел ниже | P1 |
| Пакетная обработка | Сводная таблица | Поток, мощность, угол луча, макс. сила света, КПД по всем файлам в CSV/XLSX | P1 |
| Графики | Просмотр | Полярная КСС, линейная КСС, таблица сил света, паспортные данные | P1 |
| Графики | Пакетный векторный экспорт | Графики всех файлов в SVG/PDF/EPS, в RGB или CMYK; единый стиль: шрифт, цвета, толщины, сетка, подписи, общий масштаб | P1 |
| Графики | Дополнительные | Изокандельная диаграмма, изолюксы на плоскости, 3D-тело (3D-тело поднято вперёд и сделано в v0.8, 13.11.2026: нужно для оценки операций) | P2 |
| Графики | Сравнение | Наложение двух и более файлов на одном графике | P2 |
| Расчёты | Основные | Угол луча и поля, КПД, зональные потоки, класс по CIE | P2 |
| Расчёты | Нормативные | UGR (CIE 117/190), BUG (TM-15), коэффициенты использования | P2 |
| Отчёты | PDF-паспорт | Внутреннее и наружное освещение, свои шаблоны | P3 |

## Генерация вариантов (P1)

Из одного измеренного файла создаётся по файлу на каждую комбинацию «лампа / цветовая температура»:
форма КСС та же, меняются поток и паспортные данные. Это подтверждает библиотека: в 44 из 49 групп «@ …»
КСС в кд/клм совпадают, различаются только поток и ЦТ.

1. Пользователь выбирает исходный файл и заполняет таблицу вариантов: суффикс имени, ЦТ, поток (лм)
   или коэффициент к исходному, CRI, мощность, лампа. Таблицу можно вставить из Excel.
2. Для каждого варианта силы света масштабируются на отношение потоков; в относительной фотометрии
   меняется только поток лампы.
3. Обновляются поля: в LDT — поток, ЦТ, CRI, мощность, тип лампы; в IES — поток или множитель, [LAMP],
   [_SEARCH_COLORTEMP], [_SEARCH_CRI], мощность.
4. Имя файла: «<артикул> @ <суффикс>», например «C066CL-12W3-6K-B @ 4000K». Формат IES, LDT или оба.
5. Таблица вариантов сохраняется как шаблон и применяется пакетно к нескольким исходным файлам
   (например, все цвета корпуса одной модели).

Ограничение: лампы с другим углом луча (GU10 на 45°, 60° и 120° в библиотеке) дают другую КСС, поэтому
их нельзя получить масштабированием — нужен отдельный замер. Программа предупреждает, если у лампы
указан другой угол.

## Проверка файлов (P1)

При открытии и в пакетном режиме каждый файл проверяется; результат — список предупреждений по файлу
и сводный отчёт по библиотеке. Проверки взяты из реальных дефектов, найденных в библиотеке заказчика:

- число значений силы света не совпадает с заголовком (обрезанный файл, лишнее значение);
- тип симметрии противоречит данным (Isym 1, а записано 12 разных плоскостей);
- недопустимые значения полей (Ityp 49, число ламп 0);
- разброс силы света в полюсе γ = 0° между C-плоскостями;
- измерение обрезано на γ = 90°, а свет там ещё есть;
- пары IES/LDT одного светильника расходятся по максимальной силе света или потоку;
- множитель силы света ≠ 1, относительная фотометрия вперемешку с абсолютной;
- поля названия и артикула перепутаны или не совпадают с именем файла. Правило: артикул — в [LUMCAT] (IES)
  и строке 10 (LDT), название — в [LUMINAIRE] и строке 9. Есть пакетное исправление: артикул берётся
  из имени файла, серия переносится в название, с предпросмотром изменений;
- исправление пары IES/LDT: пользователь выбирает, какой файл верный, и второй пересобирается из него
  с сохранением своих метаданных (пакетно). Пример: IES для GU10, где записан поток лампы вместо потока
  светильника.

## Этапы и приёмка

Приоритеты заказчика подняты вперёд: операции над телами и пакетная обработка идут сразу после ядра
и просмотра, расчёты — после них.

1. **Подготовка.** ТЗ согласовано; собрано 20–30 эталонных файлов и ожидаемые значения для части из них.
   - Приёмка: заказчик подтверждает ТЗ и набор файлов.
2. **Ядро форматов.** Чтение и запись IES и LDT во внутреннюю модель.
   - Приёмка: все эталонные файлы читаются; цикл «прочитал → записал → прочитал» даёт те же силы света;
     файлы открываются в DIALux / Relux.
3. **Просмотр и векторные графики.** Загрузка файла, паспорт, таблица, полярная и линейная КСС, экспорт
   в SVG/PDF/EPS (RGB и CMYK). Сделано в v0.2 (12.11.2026), графики сверены с Viso / LDT Editor 12.11.2026;
   v0.3 — оформление каталога MAYTONI, EPS с текстом в кривых (Illustrator не читает встроенный шрифт);
   v0.6 — шрифт Suisse Intl, линейная КСС в стиле каталога, экспорт PNG. Этап принят заказчиком 13.11.2026.
   - Приёмка: графики совпадают с Viso / LDT Editor; SVG открывается в Illustrator / Inkscape / CorelDRAW
     с редактируемыми линиями и текстом.
4. **Операции над телами.** Нормировка, отражение, поворот, сложение, симметризация, смена сетки.
   Сделано в v0.7 (13.11.2026): вкладка «Операции» с предпросмотром «до / после» (с v0.8 — и в 3D),
   меню «Правка» (отмена / повтор) и «Фотометрия»; 39 приёмочных автотестов. v0.9 — сглаживание
   (гауссово ядро на сфере 0…30°, с сохранением потока). Этап принят заказчиком 13.11.2026.
   - Приёмка: на эталонных примерах поток и максимум силы света совпадают с ручным расчётом; сложение
     двух копий одного тела даёт удвоенный поток.
5. **Пакетная обработка.** Рецепты, пакетная конвертация, пакетный экспорт графиков, сводная таблица,
   генерация вариантов. Сделано в v0.10 (13.11.2026): меню «Пакет» (Ctrl+B) — одно окно: файлы и папки →
   рецепт → варианты → IES / LDT, графики (polar/, linear/, общий масштаб), сводная таблица XLSX / CSV с отчётом
   проверки → ZIP; обработка в фоновом потоке с ходом работы и отменой; 23 приёмочных автотеста
   (120 файлов, 963 файла в архиве). На приёмке у заказчика.
   - Приёмка: 100+ файлов обрабатываются одним действием без зависания интерфейса.
6. **Расчёты.** Угол луча, КПД, зональные потоки, UGR, BUG, изолюксы.
   - Приёмка: расхождение с эталонными значениями в пределах согласованного допуска.
7. **Отчёты и развитие.** PDF-паспорта, TM-33, сравнение. Аккаунты и монетизация не нужны:
   инструмент внутренний.

## Открытые вопросы

- [x] Сложение тел: решено — смещение учитывается (по умолчанию 0).
- [x] Поворот: решено — вокруг Z, X и Y, всё в P1. Порядок поворотов задаёт пользователь: каждый поворот —
  отдельный шаг, видно результат после каждого.
- [x] Нормировка: решено — достаточно вариантов из таблицы функций (поток, 1000 лм, макс. сила света,
  коэффициент).
- [x] Векторные форматы: решено — SVG, PDF и EPS (RGB и CMYK); EMF и DXF пока не нужны.
- [x] Стиль графиков: образец получен 12.11.2026 («LIC eps stage2»): по нему сделано оформление полярной
  КСС «каталог MAYTONI» и одноимённый стиль — они по умолчанию. Шкала подтверждена. Шрифт — Suisse Intl
  (коммерческий, подключается с компьютера пользователя или из файлов). Несимметричные — две кривые, обе
  залиты (CMYK 0/0/20/0), перекрытие плотнее (0/0/36/0, как в образце TR106-2), C90–C270 пунктиром,
  отличным от сетки. Интерфейс — в дизайн-системе Maytoni (как «Расчёт освещения» и Track Configurator).
- [x] Пакетная выгрузка: решено — по артикулу светильника (IES: [LUMCAT], LDT: номер светильника);
  графики — тоже просто артикул; если за раз выгружается несколько типов графиков, они раскладываются
  по папкам (polar/, linear/). Имя запрашивается в диалоге при сохранении, по умолчанию — артикул.
  Нет артикула → имя исходного файла; совпадение имён → суффикс _2, _3. Решено: по умолчанию выходной файл
  называется как исходный (в библиотеке имя = артикул вместе с вариантом «@ 3000K»), в диалоге сохранения
  имя можно поправить.
- [x] Пользователи: решено — внутренний инструмент для заказчика и коллег.
- [x] Язык интерфейса: решено — русский, английский и немецкий. Язык подписей на экспортируемых графиках
  выбирается отдельно от языка интерфейса.
- [ ] Эталоны: получены библиотека MAYTONI (3 922 файла, 1 953 пары IES + LDT) и 5 лабораторных файлов.
  Нет IES LM-63-2019 — сгенерировать синтетически. Ожидаемые значения для 5–10 файлов снимаются
  в DIALux / Viso / LDT Editor.
- [x] Полярная КСС: решено — плоскость C справа, C + 180° слева; подтверждено сверкой с Viso / LDT Editor
  (12.11.2026).
